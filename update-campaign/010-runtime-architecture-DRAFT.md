## What makes v3 slow (observed in core, commit 988c38c)

- Every invocation re-walks all 37 module dirs several times in pure bash:
  test_srvctl_modules, load_libs, run_hook × (pre-init, init, post-init,
  pre/post-$CMD), hint_on_file greps every command file for help/permission
  markers (3-4 `head|grep` subprocesses per file — ~80+ command files means
  hundreds of forks just for `sc help`).
- All /etc/srvctl/*.conf sourced every run; module conditions cached in
  modules.conf but everything else recomputed.
- Heavy commands shell out per-container (to be measured per module in
  Phase A; baseline: 001-baseline.md).

## Proposed v4 shape

One node process does the thinking; bash does only what bash must (being
sourced by root shells, execing system tools interactively).

```
/bin/sc -> srvctl.sh (bash, ~30 lines: env guard, exec node)
              |
              v
          core/srvctl.mjs   (dispatcher)
              - loads /etc/srvctl config (JSON preferred, .conf parsed once
                and cached with mtime check)
              - loads command index cache (var cache, regenerated by
                update-install or on mtime drift)
              - resolves CMD -> module command
              - runs .mjs commands in-process
              - runs legacy .sh commands via ONE bash child:
                bash -c 'source runtime.sh; source <command>.sh'
                with SC_* env prepared by node
```

- `runtime.sh` = merged, trimmed lablib.sh + commonlib.sh: output helpers,
  exif/eyif, run, hint — only what command scripts actually use.
- Hooks: v3 sources every enabled module's hook at every init. v4: hook
  index cached; only hooks relevant to the invoked command run. Same
  ordering guarantees (pre-$CMD, $CMD, post-$CMD; module order preserved).
- Help/hints: generated from the cached command index (no grep storm);
  `## @en` metadata parsed once at index build.
- Target: `sc help` < 50 ms; dispatch overhead of any command < 30 ms;
  identical CLI surface.

## Compatibility rules (during the whole v4 line)

- Module tree layout unchanged (G12; see 011-module-contract-DRAFT.md).
- Every v3 command keeps working as .sh until deliberately ported to .mjs;
  the dispatcher prefers commands/<name>.mjs over commands/<name>.sh.
- /etc/srvctl/*.conf remain valid inputs; a JSON mirror is generated so
  node never re-parses bash conf at runtime.
- Root/user custom includes (/root/srvctl-includes, ~/srvctl-includes)
  keep working (sourced via the bash child path).
