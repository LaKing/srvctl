# Module containers — v3 fact sheet (commit 988c38c)

## Purpose
The heart of the container farm: creates, configures, starts, backs up, recreates and destroys systemd-nspawn containers ("VEs") under `/srv/<name>`. Owns the `srvctl-nspawn@.service` template unit, the base rootfs images under `/var/srvctl3/rootfs`, per-container nspawn/network/hosts config generation from the datastore, the default `sc <VE> <op>` command shorthand, the container status listing, hourly quota enforcement, and host-level tuning (limits/sysctl). Also provides `hs_only`/`ve_only` guards and `host-conf.js` (cluster → host.conf bootstrap) used by core `init.sh`.

## Activation
`module-condition.sh`:
- `false` if `$HOSTNAME == localhost.localdomain` (line 3).
- If `SC_HOSTNET` set or `/etc/srvctl/data` exists: `false` when `systemd-detect-virt -c` reports `systemd-nspawn` or `lxc` (i.e. we are inside a container); `true` when `/etc/srvctl/hosts.json` contains `"$HOSTNAME"` (lines 9–26).
- `true` for `CMD == update-install` with an `ARG` on any machine (bootstrap path, lines 28–32).
- Otherwise `false`. Result cached as `SC_USE_CONTAINERS` in modules.conf.
Note: `host-conf.js` is invoked directly by core `init.sh:87-99` (before module init) whenever `/etc/srvctl/data/clusters.json` exists — the module file is used even if the module is "off".

## Commands
| command | hint | behavior | side effects |
|---|---|---|---|
| (default) `command.sh` — `sc VE op` / `sc op VE` | give direct commands, or use direct shell access to containers | First sources `modules/srvctl/command.sh` (generic service handling incl. adjust-service hook). Then for ops reboot/poweroff/kill/login/show/status/shell on a dir `/srv/$C`: verifies machine running via `machinectl show`, runs `machinectl <op> $C`; `shell` execs `machinectl shell` and exits (code from exif); unreachable tail exits 35 | machinectl actions on the machine |
| add-ve NAME [TYPE] | Add a VE under a domain name, by instantiating from TYPE | Defaults TYPE=fedora; sources `$SC_ROOTFS_DIR/$T/etc/os-release`; calls `add_ve`; runs hooks `add-ve`, `add_ve_$T`, `regenerate`. If type missing: err + `ls $SC_ROOTFS_DIR`. Dynamic help `## &&& ls /var/srvctl3/rootfs` | new datastore record, `/srv/$C` tree, cert, unit enabled+started |
| add-network-ve NAME BRIDGE | Add a VE for a application in a container on br-BRIDGE | Requires `/etc/systemd/network/br-$OPA.network`; `add_ve fedora $C br-$OPA`; hooks add-ve/add_ve_fedora/regenerate; then `ssh $C firewall-cmd --zone=trusted --add-interface=host0 --permanent && reload`; prints `Done` | container on custom bridge, firewalld change inside VE |
| add-ve-user VE USERNAME | Add user to the current cluster | reseller_only + hs_only; lowercases OPA; regex-validates username (exit 22); `new user` + `regenerate_users` if missing; `add container $C user $username`; `run_hook regenerate` | datastore user + container.users, system users regenerated |
| backup-ve VE | backup container with all its files | hs_only; requires datastore `exist`; sudomize only if SC_USER is owner/reseller; `backup_ve $ARG` | rsync of `/srv/$C` to `$SC_BACKUP_PATH/srvctl-containers/$C/$NOW` (or via ssh to `SC_BACKUP_HOST`), writes container.json/dnf.packages.list/rpm.packages.list into `/srv/$C` |
| destroy-ve VE | Delete container with all its files | Like remove-ve but WITHOUT backup: removes wants-symlink, stops/disables legacy `/etc/srvctl/containers/$C.service`, `del container`, removes `/var/srvctl3/storage/static/$C`, force-umounts `/home/*/$C/*`, terminates machine, `rm -fr /srv/$C` in retry loop, prints `$C destroyed.` | destructive; datastore deletion |
| exec-all COMMAND | Execute a command on all running containers. | sudomize; `all_containers_execute "$OPAS"` — machinectl shell per local container (via temp-file trick), `ssh $host srvctl $C cmd` for remote | arbitrary command in every container |
| map-port VE [udp] PORT DESCRIPTION | Map a tcp port to the host. | hs_only, authorize, sudomize; owner/reseller check; `cfg container $C add_mapped_port "$OPAS"`; stop+start+status of `srvctl-nspawn@$C` | datastore mapped_ports, container restart; silent `exit` (0) if not owner |
| recreate-ve VE | Recreate the rootfs | hs_only; mongodump if mongo dirs exist; stop unit; `backup_ve`; `mv rootfs tmp_rootfs` (only if tmp_rootfs absent); fresh `create_nspawn_container_filesystem`; wordpress branch (start VE, `sc install-wordpress`, restore wp-content/wp-config/mysql) else copy `var/www/html/*`; restores multi-user.target.wants, /root/dump (writes mongodb.repo), mongo dirs, `/srv/*`, `/home/*`; `restore_uids`; start unit, optional codepad boilerplate install + mongorestore; exit 17 on start failure; `msg "$C READY"` | container rebuilt from base image; tmp_rootfs left behind |
| regenerate [all-hosts\|rootfs] | Update configuration settings. | hs_only; `rootfs` → `run_hook regenerate_rootfs` (from /root); `all-hosts` → `regenerate_all_hosts` (ssh each cluster host); default → `run_hook regenerate`; prints `regenerate done` | config regeneration across modules; also hourly via cron with ARG `#cron.hourly` |
| remove-ve VE | Remove container with all its files | Same as destroy-ve but calls `backup_ve "$C"` first (help text claims 7z archive in `home/.srvctl` — actually rsync backup path) | backup + destructive removal |
| status [VE] | List container statuses | with ARG: `service_action srvctl-nspawn@$C.service status` (or `$C status` if no rootfs); without: `containers_status` → node `status.js` table (ping, IP, type, disk, user, reseller, DNS flags) | read-only (systemctl/ping/dns state reads) |
| update-ve VE | Update container operating system | hs_only; stops unit; computes host `VERSION_ID`; prints `err "Feuture unimplemented"` (sic) — actual upgrade code commented out | stops the container and leaves it stopped |

## Bugs & smells
- **high** commands/recreate-ve.sh:43-48 — `tmp_rootfs` is never deleted after a successful run and the `mv` is skipped when it already exists; a second `recreate-ve` (or a re-run after success) keeps the CURRENT live rootfs and then rsyncs the STALE `tmp_rootfs` content (wp-content, mysql, home, srv) over it — silent restoration of old data over live data.
- **high** libs/statuslib.sh:27,42 — `all_containers` runs `machinectl --no-pager $cop $C` for any op other than `start`; machinectl has no `stop` or `restart` verb, so `sc all-containers stop` stops nothing and `sc all-containers restart` (after `systemctl stop` at :19) leaves every container stopped with only a machinectl usage error.
- **high** libs/backupcontainerlib.sh:30 — `run "ssh $SC_BACKUP_HOST 'mkdir -p $path'"`: `run` does not eval, so the remote shell receives the single-quoted string as one word ("command not found"); remote mkdir fails and the following rsync to the missing path aborts backup-ve via `exif` — remote backups (SC_BACKUP_HOST set) are broken.
- **medium** libs/regenlib.sh:133 — `if [[ $(get container "$C" user_ip_match) ]]` is true for both `"true"` and `"false"` output; the mismatch-repair branch (stop, update_ip, regenerate config, start) is unreachable, so wrongly-assigned container IPs are never fixed.
- **medium** commands/destroy-ve.sh:31, commands/remove-ve.sh:31, libs/backupcontainerlib.sh:10 — `[[ $SC_UID0 ]]` is always true because SC_UID0 is the string `true`/`false` (init.sh:127-132); the `err "$SC_USER has no access"` else-branches are dead and non-sudomized users fall into the root-only code path (correct form is `if $SC_UID0` as used elsewhere).
- **medium** libs/authlib.sh:4,14 — `if $SC_ON_HS` / `if $SC_ON_VE` reference variables never assigned anywhere in bash (only grep-able strings); an unset var makes the `if` body always run, so `hs_only`/`ve_only` never actually block execution — enforcement exists only via the help-listing grep in commonlib.sh:221 and module conditions; e.g. `ve_only`-marked commands of other modules run fine on hosts.
- **medium** libs/regenlib.sh:96-100 + libs/create-container.sh:37,43-48 — `check_container_directories` calls `create_nspawn_container_filesystem` for ANY `/srv` entry lacking `rootfs/` (only `/srv/TEMP` excluded); with an unknown dir the datastore `type` lookup returns empty, `[[ ! -d $SC_ROOTFS_DIR/ ]]` passes (trailing slash, dir exists), and `cp -R -p $SC_ROOTFS_DIR//*` copies ALL base images into `/srv/<straydir>/rootfs`; on an empty `/srv` the unexpanded glob even creates a literal `/srv/*` directory. The stray dir then gets os-release and is auto-imported as a container on the next regenerate (regenlib.sh:45-61).
- **medium** hooks/adjust-service.sh:28-36 — outer `if $SC_UID0` plus inner `... || $SC_UID0` makes the ownership test a tautology when root (which it always is after sudomize); the `AUTH-ERROR ... exit 142` branch is dead, so any user able to sudomize srvctl can start/stop/restart any other user's container.
- **medium** status.js:151,163 (also :96) — `users[containers[c].user].reseller`, `.type.tab(10)` and `users[SC_USER].access` throw TypeError when a container's user was deleted from users.json, the type key is missing, or the invoking user has no users.json record; the uncaught exception aborts the whole `sc status` listing (exit 99, remaining containers unlisted).
- **medium** hooks/update-install-host.sh:30 — `chown 750 /var/srvctl3/share/containers` uses a mode as owner: directory becomes owned by non-existent UID 750 instead of being chmod'ed; per-container config shared into containers lives under a bogus-owned dir.
- **low** libs/backupcontainerlib.sh:21 — `run "dnf ... list installed > /srv/$C/dnf.packages.list"`: `run` performs no redirection, `>` and the path are passed as package specs; dnf errors and `dnf.packages.list` is never written (backup metadata silently incomplete).
- **low** libs/addcontainerlib.sh:61,69 — `run cat X > Y` redirects `run`'s ANSI-colored command banner into the target file; `/var/srvctl3/datastore/cert/$C.pem` and the container's `/etc/systemd/resolved.conf` get a garbage first line (tolerated by openssl/systemd parsers today, breaks strict consumers).
- **low** libs/statuslib.sh:106 — `bash_containers_status` calls undefined `container_status` (function is named `bash_container_status`); dead code today but breaks if ever wired up.
- **low** commands/destroy-ve.sh:73-81, commands/remove-ve.sh:89-97 — unbounded `while [[ -d /srv/$C ]]; do rm -fr ...` loop; a busy/NFS-stale mount inside `/srv/$C` makes the command loop forever (3s notice interval), and `rm -fr` may follow into still-mounted data.
- **low** commands/recreate-ve.sh:125 — `rm -fr srv/"$C"/rootfs/...` misses the leading `/`; relative path deletes nothing (isolate logs kept in image).
- **low** libs/mkrootfs_arch.sh:49, libs/mkrootfs_ubuntu.sh:45 — both run `run_hooks mkrootfs_debian` (copy-paste); arch/ubuntu images get debian hooks and no distro-specific ones.
- **low** libs/mkrootfs_fedora.sh:69 — `mkdir -p "$rootfs_base"/rootfs/etc/postfix` creates a junk `rootfs/etc/postfix` directory inside the base image (intended `$rootfs_base/etc/postfix`).
- **low** libs/systemlib.sh:139,148 — `create_srvctl_nspawn_service` checks `/usr/lib/systemd/system/srvctl-nspawn@.service` but writes `/etc/systemd/system/...`; the idempotence check never matches, so every update-install rewrites (and clobbers any admin-customized) unit file.
- **low** command.sh:9-12 — GUI spec line for `show` carries action `poweroff VE` (`## spec //containers×show×show container parameters×poweroff VE`); if the external GUI executes these specs, clicking "show" powers the container off.
- **low** command.sh:85-114 — unreachable code after unconditional `exit 0` at :85 (per-binary shell lookup and `nur`/temp-file exec path is dead); command.sh:24-28 prints stray `"return from restart"` for bare `sc restart`.
- **low** libs/all_containers_quota_check.sh:25-34 — if `get container quota` errors (record anomaly), `quota` is empty and `(( size > quota ))` compares against 0, disabling and stopping a healthy container; also `SIZE_LIMIT` at :3 is dead and duplicates the datastore default.
- **low** commands/add-ve.sh:32 — sources the template's `/etc/os-release` into the running shell, overwriting host `ID`/`VERSION_ID` sourced by init.sh:118 for all subsequently run hooks in the same invocation.
