# modules/firewalld — v3 fact sheet (commit 988c38c)

## Purpose
Manages the host and container firewall via firewalld. Provides two library functions
(`firewalld_add_service`, `firewalld_offline_add_service`) that are the de facto
"open a port" API used by ~10 other modules and by datastore-generated shell code.
Its own hooks install/enable firewalld during `update-install`, open a fixed set of
web + mail ports (80, 443, 8080, 8443, 9200, 25, 143, 465, 993, 995) on hosts, in
containers, and inside the fedora rootfs template, enable IPv4 masquerade on the host
(NAT for the 10.x container network), and print firewall state during `sc diagnose`.

## Activation
`module-condition.sh`:
- `false` when `$HOSTNAME == localhost.localdomain` (line 3).
- `true` inside any container: `systemd-detect-virt -c` returns `systemd-nspawn` or `lxc` (lines 9–16; sets `readonly SC_VIRT` — subshell-scoped since conditions are sourced in `$( )` by `test_srvctl_modules`, commonlib.sh:436).
- `true` when (`$SC_HOSTNET` set OR `/etc/srvctl/data` exists) AND `/etc/srvctl/hosts.json` contains `"$HOSTNAME"` (lines 19–27; the grep pattern is the hostname in double quotes, dots unescaped).
- `true` when `CMD == update-install` and `$ARG` is set (bootstrap path, lines 29–33).
- `false` otherwise.
Result cached as `SC_USE_FIREWALLD` in `/var/local/srvctl/modules.conf` (root) or `~/.srvctl/modules.conf`.

## Libs
`libs/firewalldlib.sh` (sourced by `load_libs` only when `SC_USE_FIREWALLD=true`):

- `firewalld_add_service name proto port hint` (lines 3–49) — idempotent "open a port" on the live system: starts firewalld.service (bare `systemctl start`, line 5), reads default zone, early-returns with `ntc "firewalld: $name is enabled already."` if `--permanent --query-service` says yes; if the service is built-in (`/usr/lib/firewalld/services/$name.xml`) AND no proto/port given → `--permanent --add-service`; otherwise writes `/etc/firewalld/services/$name.xml` from a heredoc (short/description/single `<port>`), reloads, adds; final `firewall-cmd --reload`. 4th arg `hint` defaults to `$SC_USER` and lands in the XML `<description>` as `(srvctl added for $hint)`.
  **Cross-module API** — external call sites: modules/codepad/hooks/firewalld.sh:4–5, modules/ftp/hooks/firewalld.sh:3, modules/perdition/hooks/firewalld.sh:3–10, modules/postfix/hooks/firewalld.sh:3–4, modules/gluster/libs/glusterlib.sh:30, modules/named/libs/install.sh:37, modules/nfs/hooks/update-install-host.sh:7–9, modules/openvpn/hooks/update-install-host.sh:57, modules/sshpiperd/hooks/update-install-host.sh:31, modules/gui/hooks/update-install-host.sh:50, and shell code generated by modules/datastore/lib.js:665 (`firewalld_add_service port-<host_port> <proto> <host_port> <container>`).

- `firewalld_offline_add_service name proto port` (lines 51–90) — same idea against a not-yet-booted rootfs: `rootfs="$rootfs_base"` (variable contract with modules/containers/libs/mkrootfs_fedora.sh), all queries/changes via `chroot "$rootfs" firewall-offline-cmd` (offline changes are inherently permanent, no reload); writes `$rootfs/etc/firewalld/services/$name.xml` with description `(added by srvctl)`. External call sites: modules/codepad/hooks/mkrootfs_fedora.sh:11–23, modules/perdition/hooks/mkrootfs_fedora.sh:5–7, modules/postfix/hooks/mkrootfs_fedora.sh:5–6.

## State touched
- systemd units: `firewalld.service` enabled + started on hosts and in containers (update-install-host.sh:8–9, update-install-ve.sh:8–9); also bare `systemctl start firewalld.service` on every `firewalld_add_service` call (firewalldlib.sh:5).
- Host files: `/etc/firewalld/services/<name>.xml` for non-built-in services (http8080, https8443, https9200, srvctl-gui, sshpiperd, openvpn-hostnet, port-<n>, …); firewalld permanent config (default-zone service list, masquerade).
- Template rootfs: `$SC_ROOTFS_DIR/fedora/etc/firewalld/...` via chroot firewall-offline-cmd (firewalld is in the template package list, modules/containers/libs/mkrootfs_fedora.sh:37).
- Network: opens TCP 25, 80, 143, 443, 465, 993, 995, 8080, 8443, 9200 in the default zone on every managed host and container; enables IPv4 masquerade (NAT) on the host default zone.
- Module cache key: `SC_USE_FIREWALLD` in `/var/local/srvctl/modules.conf` / `~/.srvctl/modules.conf`.
- No datastore keys read or written.

## Bugs & smells
- **medium** modules/firewalld/hooks/update-install-ve.sh:5 — unconditional `sc_install firewalld`, but `sc_install` is only defined on Fedora (modules/srvctl/libs/fedoralib.sh:4 returns before defining it otherwise). On a Debian/Ubuntu/Arch container (which do get `sc` symlinks, modules/containers/libs/mkrootfs_debian.sh:35), `sc update-install` hits "command not found", every `firewall-cmd` in the subsequent `run_hooks firewalld` fails, and the hook's last command exiting 127 makes `run_hook`'s `exif` (commonlib.sh:104) **abort update-install** inside non-Fedora containers before completion.
- **medium** modules/firewalld/hooks/firewalld.sh:21-25 — unconditionally opens 8080, 8443 and Elasticsearch 9200 (plus all mail ports, lines 10–14) on **every** managed host and container regardless of whether those services exist; concrete harm: needlessly enlarged attack surface (e.g., unauthenticated Elasticsearch reachable on 9200 if it binds a public interface).
- **low** modules/firewalld/hooks/diagnose.sh:7 — uses `$zone` that this file never sets (its own declaration is commented out, line 3); it only works because modules/srvctl/commands/diagnose.sh:73 sets `zone` before `run_hooks diagnose` (line 91), and only when `/usr/sbin/firewalld` exists. If firewalld is absent (module enabled via hosts.json before first update-install) the hook runs `firewall-cmd --zone= --list-services` and prints errors; any reordering of the parent command silently breaks it.
- **low** modules/firewalld/libs/firewalldlib.sh:34-43 — when called for a name with no built-in definition and empty proto/port, writes `<port protocol="" port=""/>` into `/etc/firewalld/services/$name.xml` and reloads; an invalid service file persists on disk and can make every subsequent `firewall-cmd --reload` on that host error until removed by hand (the early-return guard at line 21 never fires because the add never succeeds, so each run rewrites the broken file).
- **low** modules/firewalld/libs/firewalldlib.sh:12 — `hint` missing from the `local` list (line 6), so a global `hint` variable leaks into the shell that sources all later hooks (benign today only because commonlib's `hint()` function declares its own local, commonlib.sh:19).
- **low** modules/firewalld/libs/firewalldlib.sh:1 — malformed shebang `#!bin/bash` (missing leading `/`); harmless while sourced, breaks direct execution and tool shebang detection.
- smell modules/firewalld/hooks/mkrootfs_fedora.sh:17-21 — dead commented-out `#fi` / `#if mail` structure; mail ports are baked into every fedora template regardless of role.
- smell modules/firewalld/hooks/diagnose.sh:5-8 — duplicates output the parent `sc diagnose` already printed (modules/srvctl/commands/diagnose.sh:70-80: zone, `--list-services`, `--list-interfaces`), so the firewall section appears twice.
- smell modules/firewalld/libs/firewalldlib.sh:5 — bare `systemctl start firewalld.service` (not via `run`, no enable) as a hidden side effect of every `firewalld_add_service` call from any module.

## Polish risks
- Function names and signatures are a cross-module ABI: `firewalld_add_service name proto port hint` and `firewalld_offline_add_service name proto port` (libs/firewalldlib.sh:3,51) — 10+ call sites in other modules and generated code from modules/datastore/lib.js:665 (`port-<n>` service names). Do not rename or reorder args.
- `hint` defaulting to `$SC_USER` (firewalldlib.sh:14-17) and the XML description strings `(srvctl added for $hint)` (line 38) / `(added by srvctl)` (line 82).
- Service names must stay byte-identical (`http8080`, `https8443`, `https9200`, hooks/firewalld.sh:21-25) — idempotency on already-deployed hosts depends on `--query-service` matching the XML files those hosts already have in `/etc/firewalld/services/`.
- XML file path pattern `/etc/firewalld/services/$name.xml` (firewalldlib.sh:34) and `$rootfs/etc/firewalld/services/$name.xml` (line 78); single `<port protocol= port=>` element shape.
- Order of operations in the non-built-in branch: write XML → `firewall-cmd --reload` → `--permanent --add-service` → final `--reload` (firewalldlib.sh:43-47); the intermediate reload is required so firewalld learns the new service before the add.
- Early-return messages `ntc "firewalld: $name is enabled already."` (firewalldlib.sh:23) and `ntc "firewalld-offline: $name is enabled already."` (line 67); `msg "Firewalld on $HOSTNAME"` (hooks/firewalld.sh:7); `msg "firewalld_offline_add_service $rootfs $name $proto $port"` (firewalldlib.sh:62).
- Default zone targeting (`firewall-cmd --get-default-zone`, firewalldlib.sh:19,63) — not hardcoded `public`.
- Masquerade enablement, both permanent and runtime, on the host default zone (hooks/update-install-host.sh:14-22) — container NAT for the 10.x network depends on it.
- `rootfs_base` variable contract with modules/containers (firewalldlib.sh:57) and the `rootfs_name == fedora` gate (hooks/mkrootfs_fedora.sh:5).
- module-condition truth table (see Activation), including `true` inside any nspawn/lxc container and the `update-install + ARG` bootstrap path — hooks fire in containers because of it.
- Hooks are sourced; the last command's exit status becomes fatal via `run_hook`'s `exif` (commonlib.sh:104). A rewrite must not turn currently-tolerated mid-hook failures into fatal ones (or vice versa).

## v4 notes
- `firewalld_add_service` and `firewalld_offline_add_service` are ~85% identical; unify into one implementation with an executor/root parameter (`firewall-cmd` vs `chroot $root firewall-offline-cmd`), or in .mjs a single `ensureService({name, proto, port, hint, root})`.
- The default port list is duplicated three times (hooks/firewalld.sh, hooks/mkrootfs_fedora.sh, modules/codepad/hooks/mkrootfs_fedora.sh) and partially overlaps postfix/perdition declarations — make it data (per-module declarative port manifest) consumed by one engine that applies it online and offline.
- The custom `firewalld` hook point is effectively a "declare your ports" registry; in v4, modules should declare ports and the firewall engine should own sequencing, install, enable, masquerade, and reload — removing per-module `systemctl start` side effects.
- `modules/datastore/lib.js:665` `container_firewall_commands()` generates `firewalld_add_service port-<n> ...` strings but has no consumer in the tree — verify before carrying it forward.
- Drop hooks/diagnose.sh (redundant with core diagnose) or make it self-contained (compute its own zone).
- Move mail-port opening to the mail modules (postfix/perdition already declare theirs) and elasticsearch 9200 to whatever module actually runs ES; default-open ports should shrink.
- module-condition's "am I a container / am I a farm host / is this bootstrap" logic is generic and repeated across modules — belongs in core context detection, with the firewalld module just declaring `enabled_in: [host, container, bootstrap]`.
